# 배포 구성과 검증 범위

2026-09-23 갱신 · 공개 릴리스 `v20260923` 기준. 최신 설치 절차는 [설치 안내](install.md)를 따른다.

## 두 기준을 구분한다

**번역 편집의 기준**은 앞선 교정이 누적된 검증본이다. **배포 델타의 source**는 지원하는 깨끗한 일본판 원본이다. 이 둘을 혼동하면 기존 번역을 잃거나 특정 구버전 패치 사용자에게만 적용되는 배포물을 만들게 된다.

```text
검증된 누적 번역본 → 이번 교정 → 후보 target
일본판 원본 + 후보 target → xdelta / ISO range pack
일본판 원본 + 배포 도구 → 재현 결과 → target 해시 대조
재현 결과 + 백업 → 복구 결과 → 원본 해시 대조
```

## 이번 교정의 구조적 경계

- 이슈 #7: Logic 10개 엔트리의 대사 필드 44개. 기존 고정 필드, 엔트리 길이와 줄 제어를 유지한다.
- 이슈 #9: 초반 대사 4개, General2d 퀵 커맨드 49곳, General3d 지형 제목 405개(87종).
- 퀵 커맨드의 WTD 길이 필드와 `<X=...></X>` 제어 태그를 보존한다.
- 지형 `landinfo.mti`는 MPTI 헤더 12바이트와 1,024개의 84바이트 레코드다. 각 레코드 첫 64바이트는 NUL 종료 문자열 영역, 뒤 20바이트는 수치 데이터다. 제목과 `@` 뒤 내부 설명을 구분하고 수치 영역은 변경하지 않는다.
- Battle 참조 복구와 Common 최신 폰트는 이번 교정 과정에서 유지한다.

위 수치는 지정 배치의 수정 단위다. 전체 게임 번역 문장 수나 전체 한글화율을 뜻하지 않는다.

## ELF 시스템 문구와 별도 런타임 패치

아카이브 재생 중단 확인창은 아카이브 내 번역 데이터와 별도로 실행 파일에 있는 문구다. 문자열을 PSARC에서 찾지 못했다고 이미지라고 단정하지 않는다.

해당 분석에서 ELF 파일 오프셋은 `0xDBA070`, PT_LOAD 매핑으로 확인한 가상 주소는 `0xDCA070`이었다. 이 차이를 다른 파일이나 주소에 일괄 적용해서는 안 된다.

```text
segment.p_offset <= file_offset < segment.p_offset + segment.p_filesz
virtual_address = segment.p_vaddr + (file_offset - segment.p_offset)
```

대상 52바이트 영역에 프록시 문자열 47바이트와 NUL 패딩을 넣는 RPCS3 `bd32` 13개 패치를 제공한다. 대상 PPU 키는 `PPU-e429bb11d03c2e6a046775179d21169cba555c47`이며 패치명은 `OGMD archive replay-question Korean 20260918`이다.

**이 수정은 ISO의 EBOOT.BIN을 바꾸지 않는다.** `RPCS3_optional`의 YAML을 별도로 가져와 활성화해야 한다. Common 한글 폰트가 필요하며, 다른 실행 파일 해시에는 적용을 보장하지 않는다. 기존 설정 파일을 통째로 덮어쓰지 않는다.

## 확인된 시험과 확인하지 않은 시험

배포물의 `release_validation.json`에 기록된 결과다. 이번 문서 갱신에서 게임을 새로 실행해 얻은 결과가 아니다.

| 검사 | 결과 | 한계 |
|---|---|---|
| 원본에 xdelta 적용 | 7개 target 해시 일치 | 실제 화면 검사가 아님 |
| 실제 EXE로 ISO 적용 | 시험 ISO 내 7개 파일 해시 일치 | 소매판 전체 ISO 배치와 다름 |
| EXE로 ISO 복구 | 시험 ISO 전체 해시 원상복구 | 모든 ISO 변형을 시험한 것은 아님 |
| 폴더 설치·검증·복구 | 통과, 7개 결과 대조 | 모든 사용자 경로/장애 상황을 검증한 것은 아님 |
| 수정시각 | 시험에서 보존 확인 | 모든 손상 경고의 부재를 보장하지 않음 |
| ZIP 내부 파일 | SHA256SUMS 대조 | ZIP 전체 해시와 구분 |
| 공개 다운로드 | ZIP 크기·해시 일치 | 게임 실행 성공을 뜻하지 않음 |
| 이번 변경의 게임 화면 | 미완료 (`runtime_tested: false`) | 사용자 장면별 확인 필요 |

ISO 시험은 7개 원본 파일의 전체 payload와 실제 내부 경로를 넣은 **축소 ISO9660 fixture**를 사용했다. Battle을 분할 익스텐트로 배치해 경계를 넘는 읽기·쓰기와 복구를 확인했다. 원본 소매 ISO의 전체 디스크 배치 시험 또는 PS3 실기 시험으로 표현하지 않는다.

## 배포 산출물 일치성

새 target을 만들면 xdelta만 바꾸지 말고 다음을 함께 대조한다.

1. source/target 파일 크기·SHA-256 명세.
2. xdelta 7개와 ISO range pack의 대상 집합·결과 해시.
3. range pack을 내장한 실제 EXE.
4. install/verify/restore 스크립트의 기대 해시와 대상 수.
5. 선택형 런타임 YAML의 주소·PPU 키·활성화 안내.
6. 배포 ZIP 내부 체크섬, ZIP 전체 해시, 공개 다운로드 결과.

v20260923 ZIP은 107,431,851바이트이며 SHA-256은 `B4C8FC1AE7B2ACDD1FE2124B4E6C184CD57F970C0BA4760AA0E594998B59B3C2`이다. 문서만 고쳐 main에 게시한 것은 기존 ZIP을 교체했다는 뜻이 아니다. ZIP의 체크섬 목록을 현재 웹 문서 파일의 해시 목록으로 해석하지 않는다.

## 후속 작업 인계에 남길 항목

입력 파일의 출처·해시, 누적 교정 기준, 변경 엔트리·필드, 비대상 엔트리 불변 검사, 구조·참조 검사, 후보 해시, 적용·복구 로그, 수정시각, 실제 설치 여부, 실행 시험 여부를 따로 기록한다.

로컬 릴리스 스테이징 스크립트는 경로와 기존 산출물에 의존하며 재실행 시 덮어쓰기·중복 상태가 생길 수 있다. 과거 번호 순서대로 무조건 재실행하지 않는다. 공개 도구만으로 번역 데이터 없이 완성 배포물을 재현할 수 있다고 주장하지 않는다.
