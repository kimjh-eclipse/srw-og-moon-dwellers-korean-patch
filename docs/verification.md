# 실기 검증과 오판 정정

배포 직전 타이틀 화면이 흰색으로 표시되는 현상이 나타났다. 원인 후보를 하나씩
배제한 기록이다. 결론부터 적으면 **한국어 패치와 무관한 조기 입력 문제**였다.

## 증상

1. 로고 애니메이션이 끝난 뒤 잠시 흰 화면이 나온다
2. 여기서 버튼을 누르면 화면이 검게 바뀐다
3. 타이틀 화면(`PRESS ANY BUTTON`)이 표시되지 않는다
4. 이후 메뉴는 **커서 이동·선택·사운드가 정상 동작하지만 화면만 흰색**이다

4번이 결정적인 단서였다. 로직이 살아 있고 그림만 안 나온다면 텍스트·스크립트 데이터
손상이 아니라 그래픽 리소스 또는 화면 전환의 문제다.

## 배제 과정

### 후보 1 — 한국어 패치 회귀

가장 먼저 의심할 대상이지만, 다음이 이미 확인돼 있었다.

- 설치 전 4개 파일 해시 = 이전에 정상 확인된 최종 빌드
- 설치 후 4개 파일 해시 = 동일한 값

**비트 단위로 같은 파일**에서 결과가 달라질 수는 없다. 그래도 확실히 하려고
원본 4개로 되돌려 같은 절차를 재현했고, **원본에서도 동일하게 발생**했다.

→ 배제.

### 후보 2 — 게임 데이터 누락

HDD 설치본에 `Sound.psarc`, `Movie.psarc`, `PSARCLIST.BIN`이 없었다.
로그에도 `CELL_ENOENT`가 찍혔고, 직후 `MoviePlayer` 스레드와 `libsail`(동영상 재생 모듈)이
뮤텍스 오류를 뱉었다. 오프닝 동영상을 못 읽어 화면이 멈추는 그림과 맞아 보였다.

ISO에서 세 파일을 추출해 설치하고 재현했다. **동일했다.**

→ 배제.

> **여기서 오판이 하나 있었다.** 로그의 `dev_bdvd` 폴백 실패 라인은 `Dat/` 하위
> 텍스처와 디렉터리 건이었는데, 이를 `Sound`/`Movie`까지 일반화해 "디스크 폴백도
> 실패했다"고 적었다. 실제로는 폴백이 정상 동작하고 있었다. 발췌 몇 줄로 전체를
> 단정한 것이 잘못이었다.

### 후보 3 — 에뮬레이터 버전 회귀

실행 중인 RPCS3가 폴더 이름(`v0.0.27`)과 달리 **v0.0.42-19699**였다.
`rpcs3.exe`가 검증 시점 전후로 교체된 이력이 있어 회귀를 의심했다.

이전 버전에서도 동일하게 재현되는 것이 확인됐다.

→ 배제.

### 실제 원인 — 전환 중 조기 입력

세 후보가 모두 빠지고 남은 변수는 **조작 타이밍**이었다.

- 로고 뒤 흰 화면에서 **아무 버튼도 누르지 않고 기다리면** 타이틀 화면이 정상 표시된다
- 그 흰 화면에서 **먼저 누르면** 백화가 재현된다
- 원본 파일 조합에서도 같은 조건으로 재현된다

타이틀 리소스 초기화가 끝나기 전에 입력이 들어가 화면 전환 시퀀스가 어긋나는 것이다.
회피 방법은 `PRESS ANY BUTTON`이 실제로 표시된 뒤에 입력하는 것이다.

## 로그 대조

패치본 세션과 원본 세션의 RPCS3 로그를 대조했다. 오류 프로필이 한 줄씩 대응했고,
양쪽 모두에서 다음이 **없었다**.

- SDAT 복호 실패
- PSARC 파싱 실패
- Fatal / Assertion

즉 패치가 만든 파일은 정상적으로 읽히고 있었다.

## 배운 것

**동일 해시 파일에서 다른 결과가 나오면 파일을 의심하지 말고 환경과 조작을 의심한다.**

해시 대조를 설치 전후 양쪽에서 해 두지 않았다면 이 판단에 훨씬 오래 걸렸을 것이다.
검증 절차에 해시 기록을 넣어 두는 것은 원인 규명 비용을 크게 줄인다.

또 하나. **원인 추적 중에 나온 관찰을 결론으로 승격시키지 않는다.**
`Sound`/`Movie` 누락은 사실이었지만 원인은 아니었고, 폴백 실패는 사실도 아니었다.
로그 발췌 몇 줄에서 전체를 단정하면 이렇게 어긋난다.

## 배포 판정

이 현상은 배포 차단 사유가 아니다. 원본에서 재현되고, 회피 방법이 명확하며,
게임 진행에 지장이 없다. 다만 사용자가 반드시 알아야 하므로 README의 알려진 문제에
회피 방법과 함께 명시한다.

단, 다음은 계속 실패로 판정한다.

- 크래시
- 기다려도 타이틀이 영구히 표시되지 않는 경우
