# 빌드 파이프라인

원본 게임 데이터에서 출발해 배포 가능한 패치까지 가는 전체 절차다. 2026-09-19 기준으로 [BMD 참조·폰트 검사](bmd-font.md)와 [현재 배포 검증](release-validation.md)을 함께 적용한다. 아래 초기 번역 통계는 당시 작업 기록이다.

```
ISO / HDD 설치본
   └ SDAT 복호                     sdat.py
       └ PSARC 파싱                psarc.py
           └ 텍스트 추출·번역
               └ 고정 배치 재빌드  psarc_fixed_blocks.py
                   └ SDAT 재암호화 sdat_encode.py
                       └ xdelta 델타 생성
                           └ 왕복 검증
                               └ 배포 묶음
```

## 1. 원본 확보

xdelta의 source가 되는 원본은 **한 벌만** 쓴다. 중간 산출물이나 이전 패치본을
source로 쓰면 그 패치를 이미 적용한 사람에게만 동작하는 델타가 나온다.

v20260919 대상은 PSARC 5개와 제목·아이콘 2개이다. 크기와 SHA-256을 고정해 매 단계에서 대조한다. 아래 번역·압축 측정치는 초기 빌드 기록과 구분해 읽는다.

| 파일 | 크기 | SHA-256 |
|---|---:|---|
| `Common` | 505,828,992 | `99B298B3…2093BB` |
| `General2d` | 611,585,392 | `04C3D1DA…F16667` |
| `General3d` | 870,220,816 | `A702DB12…02B412` |
| `Logic` | 38,399,120 | `AF453B39…F5F181` |
| `Battle` | 1,729,186,848 | `2C5CA16F…F894A844` |

## 2. 추출과 번역

`Battle`은 1.7GB이므로 전체를 디스크에 풀지 않고 `SDATReader`로 필요한 구간만 복호한다.

전투 대사는 기계 번역 결과를 그대로 쓰지 않았다. 캐릭터별 성향과 말투를 기준으로
직접 검토하고, 고정 슬롯에 맞춰 축약했다.

```
직접 검토한 고유 원문      31,076
실제 BMD 출현              40,248
최종 적용                  40,248
고정 슬롯 초과             0
SDAT 블록 해시 오류        0
```

메뉴·UI는 칸 폭 제약이 강하다. 좁은 칸에서는 `특수 스킬`을 `특수기`로 줄이는 식으로
표기를 따로 뒀다.

## 3. 재빌드

표준 재패킹이 아니라 [고정 배치 재빌드](fixed-layout.md)를 쓴다.
이 단계를 표준 방식으로 하면 배포 델타가 수백 배 커진다.

## 4. 델타 생성

```
xdelta.exe -e -9 -f -B 67108864 -s <원본> <최종빌드> <패치>
```

`-B`(source window)는 기본 64MiB로 충분하다. 고정 배치 재빌드를 거쳤다면
매칭이 같은 오프셋에서 일어나므로 창을 키워도 이득이 없다.

## 5. 왕복 검증 — 생략 불가

각 델타를 **원본에 다시 적용**해 결과의 SHA-256이 최종 빌드와 일치하는지 확인한다.

```
xdelta.exe -d -f -s <원본> <패치> <복원본>
Get-FileHash -Algorithm SHA256 <복원본>
```

하나라도 어긋나면 배포를 중단한다. 이 검증은 "패치가 만들어졌다"가 아니라
**"시험한 원본과 도구 조합에서 기대 파일이 재현된다"**를 확인한다. 사용자 환경 전체와 실제 화면의 정상 동작까지 보장하지 않는다.

## 6. 배포 묶음

원본 PSARC/SDAT나 ISO는 절대 포함하지 않는다. 델타와 스크립트, 문서만 넣는다.

```
install_xdelta.ps1          안전 설치
verify_xdelta.ps1           설치 상태 확인
restore_xdelta_backup.ps1   원본 복구
xdelta.exe           패치 적용 도구
patches/             델타 7개 (PSARC 5개 + 제목·아이콘)
OGMD_ISO_QuickPatch.exe     ISO / 폴더 GUI
RPCS3_optional/            별도 아카이브 팝업 런타임 패치
README / CHANGELOG / SHA256SUMS
```

### 설치 스크립트가 지켜야 하는 순서

1. RPCS3 실행 여부 확인 — 실행 중이면 중단
2. 대상 게임 ID와 실제 PSARC 경로를 확인. 디스크 원본의 `PS3_GAME/USRDIR/PSARC`와 hdd0 설치본을 구분
3. 원본 PSARC 5개의 크기와 SHA-256 검증; 제목·아이콘은 별도 지원 원본 검사
   - 이미 패치된 해시면 중단하고 복원을 안내한다
4. 원본을 날짜가 붙은 폴더에 백업 — **게임 데이터 폴더 밖에** 만든다
5. **임시 파일**에 델타 적용. 대상 파일에 직접 쓰지 않는다
6. 임시 결과의 크기와 SHA-256 검증
7. 검증을 통과한 결과만 교체
8. 원래 수정시각(UTC) 복원
9. 최종 해시 출력

실패했을 때 원본을 자동 삭제하거나 게임 폴더를 지우지 않는다. 복구 명령만 안내한다.

PSARC 복구는 원본 해시를 검사한다. 제목·아이콘은 백업이 있으면 복사하므로 해당 설치의 신뢰할 수 있는 백업만 사용한다.
그러지 않으면 패치본을 백업으로 착각해 덮어쓰는 사고가 난다.

## 7. 누적 빌드와 배포 전 검사

소매판은 배포 델타의 source이고, 누적 번역본은 편집 기준이다. 최신 릴리스 파일명만 보고 중간 빌드로 바꾸지 않는다. Common·Battle을 포함한 전체 입력 해시를 잠그고 지정 엔트리 외 변경이 없는지 대조한다.

문자열 검사는 인코딩, NUL, 제어 태그, 바이트 용량을 다룬다. 전투 BMD는 헤더 기반 line 포인터와 문자열 순번까지 검사한다. PSARC 재빌드 뒤에는 엔트리를 역읽기하고 SDAT 크기 및 최종 해시를 확인한다.

배포 단계는 xdelta, ISO range pack, 내장 EXE, 설치·검증·복구 기대 해시를 같은 target으로 맞춘다. 실제 EXE의 ISO 시험과 폴더 스크립트 시험을 각각 기록하고 ZIP 내부 체크섬과 공개 다운로드 해시까지 확인한다. 실행 시험은 별도 항목으로 기록한다.

현재 시험의 범위와 한계, 7개 target 해시는 [배포 구성과 검증 범위](release-validation.md)에 있다. 초기 번호의 작업 스크립트를 모두 순서대로 실행하는 것을 최신 빌드 방법으로 안내하지 않는다. 비공개 번역·자산 데이터와 경로 설정이 필요한 도구가 있다.

## 8. 클론·배포 시 바이트 보존

패치를 git으로 배포한다면 줄바꿈 정규화를 꺼야 한다.

```
# .gitattributes
* -text
```

끄지 않으면 클론 시 스크립트와 텍스트 파일의 CRLF 변환으로 바이트가 달라져
`SHA256SUMS.txt`와 어긋난다. 새로 클론해 해시를 대조하는 것까지 검증에 포함한다.
