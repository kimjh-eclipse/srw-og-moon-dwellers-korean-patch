# 전투 대사 참조와 폰트 처리

2026-09-19 갱신. 현재 공개 소스의 `tools/bmd_rebuild.py`, `tools/258_repair_battle_references.py`, `tools/263_verify_battle_refs_full.py`를 기준으로 한다. 이 문서는 게임 대사 원문이나 번역 대역표를 포함하지 않는다.

## 문자열이 정상이어도 대사가 비는 이유

문자열 풀에서 번역문을 찾았다는 사실만으로 해당 대사가 정상 표시된다고 판단할 수 없다. 게임은 line 레코드가 가리키는 위치에서 문자열을 읽는다. 참조가 NUL, 문자열 중간 또는 다른 문자열을 가리키면 본문이 존재해도 빈 창·잘린 첫 글자·다른 대사가 나타날 수 있다.

따라서 검사 대상을 세 층으로 나눈다.

| 층 | 검사 | 이것만으로 알 수 없는 것 |
|---|---|---|
| 문자열 | 번역문, UTF-8, NUL 종료, 제어문자 | 게임이 그 문자열을 참조하는지 |
| 참조 | 구조상 포인터, 풀 상대 주소, 문자열 순번 | 폰트가 올바른 글리프를 그리는지 |
| 표시 | 코드 매핑, 글리프, 폭·간격, 실제 장면 | 다른 모든 분기까지 정상인지 |

전각 공백 변경 뒤 증상이 보였다는 시간적 순서만으로 공백이나 폰트를 원인으로 확정하지 않는다. Battle과 Common의 해시를 함께 기록하고 참조부터 독립적으로 확인한다.

## 버전 3 BMD 레이아웃

지원하는 헤더의 첫 2바이트는 `03 00`이다. 오프셋 2에서 group/event/line 개수를 각각 16비트 빅엔디안으로 읽는다.

| 영역 | 크기 |
|---|---:|
| 헤더 | 8바이트 |
| group 레코드 | 개수 × 12바이트 |
| event 레코드 | 개수 × 20바이트 |
| line 레코드 | 개수 × 20바이트 |
| 문자열 풀 | NUL 종료 UTF-8 문자열 |

```text
line_start = 8 + group_count * 12 + event_count * 20
pool_start = line_start + line_count * 20
pointer_field(i) = line_start + i * 20 + 16
text_address = pool_start + BE32(pointer_field(i))
```

`FFFFFFFF`는 sentinel이므로 주소로 해석하거나 재배치하지 않는다. line 레코드의 마지막 4바이트만 검증된 문자열 참조다. 헤더 전체에서 문자열 오프셋과 값이 같은 정수를 찾아 바꾸는 방식은 금지한다. 같은 값의 메타데이터까지 수정할 수 있기 때문이다.

## 풀 시작을 문자열 검색으로 추측하면 안 되는 이유

과거의 긴 UTF-8 문자열 검색 방식은 포인터 테이블 끝의 바이트가 우연히 출력 가능한 문자일 때 테이블과 풀 경계를 걸쳐 매칭했다. 복구 코드가 다루는 사례에서는 구조상 풀보다 최대 2바이트 앞에서 시작할 수 있었다.

현재 버전 3 파서는 헤더 개수로 풀 위치를 계산한다. 다른 헤더에 남아 있는 검색 fallback은 다른 형식의 구조가 검증되었다는 뜻이 아니다. `replace_variable()`은 `layout()`을 통해 버전 3 구조를 요구한다.

## 두 편집 방식의 계약

### 고정 필드 교체: `replace()`

기존 문자열의 NUL 포함 바이트 용량 안에서 교체하고 남는 공간을 0으로 채운다. 이 함수는 초과 문자열을 문자 경계에서 자르고 잘림 수를 반환한다. **호출 성공을 번역 무손실 성공으로 취급하면 안 된다.** 배포 작업은 잘림을 별도 오류 또는 검수 대상으로 처리해야 한다.

### 문자열 풀 재구성: `replace_variable()`

문자열 순서대로 새 풀을 만들고 `기존 상대 시작 주소 → 새 상대 시작 주소` 표를 생성한다. 구조로 구한 line 포인터만 새 주소로 갱신한다.

- 명시한 풀 시작과 헤더로 계산한 시작이 같아야 한다.
- sentinel 외 모든 참조는 기존 문자열 시작이어야 한다.
- 구현은 모든 파싱된 문자열의 참조 커버리지를 요구하며, 입증하지 못하면 중단한다.
- 풀 앞의 메타데이터와 풀 뒤 데이터는 보존한다.

이 함수는 가변 크기 결과를 만들 수 있다. 결과가 PSARC 원본 슬롯에 들어가는지, 컨테이너 크기를 유지할 수 있는지는 별도 검사다. 문자열 재배치 성공과 아카이브 재빌드 성공은 다른 조건이다.

## 참조 복구는 번역 롤백이 아니다

`258_repair_battle_references.py`는 게시 번역본의 본문을 유지하면서 소매판의 검증된 구조·메타데이터를 기준으로 참조를 복원한다.

1. 입력 번역본 해시를 고정한다.
2. 소매판 구조와 문자열 순번의 대응을 구한다.
3. 비포인터 메타데이터 변경이 잘못된 오프셋 치환으로 설명되는지 검사한다.
4. 번역 문자열 풀을 구조상 올바른 위치에 놓는다.
5. 소매판과 같은 문자열 순번을 참조하도록 line 포인터만 쓴다.
6. sentinel, 문자열 순서·본문, BMD 크기 및 비대상 PSARC 엔트리를 확인한다.

v20260923도 이 참조 수정본 Battle을 그대로 유지한다. 구버전 Battle로 교체해 증상만 회피하면 이후 인명·대사 교정이 함께 빠질 수 있으므로, 파일 날짜나 이름이 아니라 해시와 엔트리 차이를 대조해야 한다.

## 참조 전수 검사

`263_verify_battle_refs_full.py`의 핵심은 단순 범위 검사가 아니라 **소매판과 수정본이 같은 순번의 문자열을 참조하는지** 비교하는 것이다.

- 참조가 풀 안에 있는가?
- NUL 사이 문자열의 정확한 시작인가?
- 소매판과 동일한 line이 동일한 문자열 순번을 가리키는가?
- sentinel 위치가 유지되는가?
- 기준 번역본의 문자열 집합·순서·본문이 유지되는가?

주의: 이 도구의 `원문 그대로 남은(미번역)` 집계는 원문과 문자열이 같은지를 세는 지표다. 숫자·기호·고유명사가 같을 수도 있으므로 그 수치를 실제 미번역 대사 수로 단정하지 않는다. 해당 스크립트는 로컬 작업 경로를 사용하므로 입력 파일과 해시를 확인한 뒤 실행해야 한다.

## 폰트·공백 회귀 검사

이 프로젝트는 게임용 폰트에 한글 글리프를 넣고 대체 코드로 문자열을 인코딩한다. 디코딩된 한글, 저장된 UTF-8 바이트, 화면에서 그려지는 글리프는 구분해야 한다.

- 실제 저장 바이트 기준으로 용량을 계산한다. 한글 글자 수만 비교하지 않는다.
- ASCII 공백과 전각 공백은 바이트 길이와 표시 폭이 다르다. 전역 치환 전에 해당 컨테이너의 참조 갱신 조건을 확인한다.
- `@` 줄 제어, `<X=...></X>` 같은 UI 태그, 용어 링크와 아이콘 코드를 일반 문장과 분리한다.
- 폭 0인 글리프의 존재만으로 회귀라고 판정하지 않는다. 이전 폰트와 사용 코드·메트릭을 비교한다.
- Common 폰트와 Battle·Logic 등 텍스트 파일의 조합을 해시로 기록한다.
- 리오·아케미·라이의 문제 장면뿐 아니라 도감, 아카이브, 숫자·L 표기, 시스템 글꼴로 그리는 세이브 목록도 구분해 확인한다.

파일 검사 통과 후에도 실제 장면의 줄바꿈·간격·렌더링은 별도 사용자 테스트가 필요하다.
